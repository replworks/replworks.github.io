## [DRAFT] 2026-05-31: 애플 인텔리전스 온디바이스 개발 시 반드시 알아야 할 버퍼 최적화 팁

### 개요

아이폰 15 프로의 로컬 LLM을 활용해 서버 없는 영어 회화 앱을 만들다가 컴파일 지옥과 앱 크래시를 맛보았습니다. 결론부터 말씀드리면, `AVAudioEngine`과 애플 내장 Local LLM API 간의 숨겨진 샘플 레이트(Sample Rate) 미스매치 때문이었습니다. 1인 개발실에서 서버 비용 0원에 도전하며 이 버그를 우아하게 깨부순 과정을 공유합니다.

### 1. 지옥의 에러 코드 -50을 만나다

처음에는 실시간 음성 인식을 위해 오디오 버퍼 사이즈를 1024로 넉넉하게 잡았습니다. 하지만 애플의 기기 내장 파운데이션 모델은 생각보다 엄격했습니다. 입력 텐서(Tensor) 포맷이 일치하지 않자 가차 없이 앱이 터져나갔죠.

### 2. AI 셰프 중간에 끼워 넣기: AVAudioConverter

우리가 선택한 해결책은 뼈대를 전면 재작성하는 무모한 짓이 아니었습니다. `AVAudioEngine`의 출력단과 LLM 입력단 사이에 `AVAudioConverter`라는 경량 다운샘플링(Downsampling) 레이어를 플러그인 형태로 주입하는 아키텍처적 솔루션을 도입했습니다.

```swift
// AI 라이터가 이해를 돕기 위해 JOURNAL.md에서 긁어와 정제한 핵심 코드 스냅샷
let converter = AVAudioConverter(from: inputFormat, to: targetLLMFormat)
// ...실시간 포맷 변환 루틴 구동
```

### 3. 인디 해커로서 얻은 교훈

외부 무거운 라이브러리에 의존했다면 원인 분석에만 일주일이 걸렸을 것입니다. 애플의 순정 프레임워크(AVFoundation) 안에서 관심사를 분리하고 상태 머신을 단순하게 유지하는 것, 이것이 1인 AI 개발자가 속도를 유지하는 유일한 비결입니다. 서버 비용 '0원'으로 돌아가는 온디바이스 AI의 세상은 생각보다 훨씬 매력적입니다.
