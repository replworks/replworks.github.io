Follow AGENTS.md.
Read the documents in DOCUMENT_ORDER:

- PRODUCT_SPEC.md
- TECH_STACK.md
- ARCHITECTURE.md

Treat these three documents as the entire implementation contract.
Ignore TASKS.md.

The purpose of this check is to find what the documents cannot settle
by themselves before implementation starts.
Details that an implementer can choose while implementing
are not the concern of this check.

## Step 1: Contract check

Assume the repository is empty and no additional information will be provided.
Existing source code is not evidence that the contract is sufficient.

Dry-run the implementation of the entire product.
For every behavior stated in PRODUCT_SPEC.md, determine:

- which component owns it
- what its inputs and outputs are
- how data reaches it and leaves it
- where it is implemented under the constraints in TECH_STACK.md

A point is blocking only if ALL of the following hold:

- two reasonable implementations would differ in behavior that a Developer,
  a Payer, or an external system can observe at a component boundary
  or at the product boundary
- the three documents give no rule that selects between them
- PRODUCT_SPEC.md claims the behavior

Also blocking, regardless of the test above:

- contradictions between the documents (apply the priority in AGENTS.md)
- behavior that depends on an external boundary
  with no recorded observation or spec and no [UNVERIFIED] mark
- sections marked [UNVERIFIED]

Not blocking. Do not report:

- names: identifiers, public symbols, table names, keys, constants
- values of constants and the types of identifiers
- how two parts of the product are wired together,
  when the implementer can choose while implementing
- the order of items when no order is required
- internal structure inside a component
- anything AGENTS.md lets the implementer resolve with a neutral placeholder
- decisions already recorded in ARCHITECTURE.md Resolved Decisions
- behavior PRODUCT_SPEC.md does not claim
- content and visual design

## Step 2: Code divergence check

Run this step only if the repository contains source code.

Report as blocking only:

- code that contradicts the three documents
  (including TECH_STACK.md versions and folder rules)
- behavior the code already implements that PRODUCT_SPEC.md does not state

Documented behavior that is not implemented yet is not a divergence.

## Rules

Do not write code.
Do not create or modify any file.
Do not run commands or call external services.
Do not answer the questions.
Do not suggest improvements, new features, or alternative technologies.

## Output

Output only a numbered list of questions in chat,
most blocking first, at most 7.
Report all [UNVERIFIED] sections together as one question.
If more than 7 questions qualify, keep the 7 most blocking.

Each question must state:
- which step it comes from (1 or 2)
- which document and section it concerns (and which file, for step 2)
- what is undefined or conflicting
- which observable behavior would differ, so that you cannot proceed
  without an answer

If no blocking questions exist, output exactly:

Implementation can begin with high confidence.
