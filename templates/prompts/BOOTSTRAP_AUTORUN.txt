AGENTS.md 읽어. 그리고 TASKS 개발 시작해.

아래는 AGENTS.md의 "Stop and ask the human"을 어떻게 수행하는지에 대한 추가 규칙이다.
AGENTS.md의 다른 규칙은 하나도 바꾸지 않는다. 충돌하면 AGENTS.md가 우선이다.
단, "사람에게 묻는 방법"만은 이 규칙을 따른다.

## 질문 방법

### 1단계: 첫 태스크 브랜치를 만들기 전 (bootstrap)
- 지금처럼 세션 대화창에서 나에게 직접 묻는다.
- ask-human.sh 를 쓰지 않는다. 폴링하지 않는다.

### 2단계: 첫 태스크 브랜치를 만든 이후 (AUTO_RUN 시작 후)
- 나에게 물어야 하는 상황(AGENTS.md의 "Stop and ask" 조건)이 생기면
  세션 대화창에 질문을 쓰고 턴을 끝내지 않는다.
  반드시 GitHub 코멘트로 묻고, 내 답이 올 때까지 기다렸다가 이어서 진행한다.
- 질문하지 않고 추측해서 진행하지 않는다.

채널 선택:
- 현재 브랜치에 코드 변경이 있다(main 대비 커밋이 있거나 커밋 안 된 변경이 있다)
  -> PR 채널
- 코드 변경이 없다 -> Issue 채널

PR 채널:
1. 현재 브랜치에 PR이 없으면: 커밋 안 된 변경은 `chore: wip t-NNN` 으로 커밋(bot account),
   브랜치를 push 하고 bot account 로 draft PR을 연다
   (Conventional Commits 제목, assignee: bot account).
   이 draft PR이 그 태스크의 최종 PR이다. 두 번째 PR을 만들지 않는다.
   태스크가 끝나면 이 PR을 ready 로 전환해서 AUTO_RUN 6번을 수행한다.
2. `.replworks/scripts/ask-human.sh ask pr "<질문>"` 을 실행한다.

Issue 채널:
1. `.replworks/scripts/ask-human.sh ask issue "<질문>"` 을 실행한다.
   질문 하나에 이슈 하나다. 질문 때문에 커밋/push/PR을 만들지 않는다.

질문 형식:
- 객관식을 기본으로 하되, 안 맞으면 자유 응답 허용. 선택지 2~4개, 각 한 줄.
- 권장안에 "(recommended)" 를 붙인다.
- 코드가 어떻게 동작하는지가 아니라 "무엇이 맞는지"를 묻는다.
- 관련 문서 섹션이나 diff 링크를 넣는다.
- 나는 폰에서 5초 안에 답한다고 생각하고 쓴다.

답 기다리기:
1. ask 가 출력한 값이 토큰이다. `.replworks/scripts/ask-human.sh wait <토큰>` 을 실행한다.
2. 출력이 `PENDING` 이면 같은 명령을 그대로 다시 실행한다. 최대 120회 반복한다.
   반복하는 동안 다른 작업이나 설명을 하지 않는다.
3. `PENDING` 이 아니면 그 출력이 내 답이다. 답대로 이어서 진행한다.
4. 120회가 지나도 답이 없으면, 어느 태스크의 어떤 조건에서 기다리는지를
   그 PR 또는 이슈에 코멘트로 남기고 멈춘다.
   TASKS.md 를 수정하지 않는다. 임의로 진행하지 않는다.

ask-human.sh 가 에러를 내면(PR 없음 등) 에러 메시지를 읽고 위 절차대로 고친 뒤 다시 실행한다.
스크립트 자체가 동작하지 않으면 그 사실을 세션 대화창에 보고하고 멈춘다.
