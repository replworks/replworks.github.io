## 실무 IDEAS.md 작성 예시

아래 예시는 REPL Works 프레임워크 자체를 개발할 때 아이디어 정제 단계에서 실제로 사용한 `IDEAS.md` 문서 규격입니다.

<MissionBox text="IDEAS.md는 아이디어를 장황하게 설명하지 않고, 타겟 문제와 시장성, 가설을 사업적으로 검증합니다." />

```markdown
# IDEAS.md

Version 4.0

# Project

REPL Works

REPL Works는 생각(Thinking)과 실행(Execution)을 분리하고,
프로젝트 지식을 Git 문서 자산으로 보존하여 사람, 세션, 모델이 바뀌어도
개발 연속성을 보장하는 AI-Native Product Development Framework입니다.

# Vision

AI 모델은 점점 더 강력해지고 있습니다.
더 긴 Context Window, 더 강력한 Agent Runtime, 빠른 코드 생성 속도.

그러나 개발 현장에서는 동일한 문제가 반복됩니다:

- 채팅 세션이 길어지면 프로젝트 의도와 설계 맥락이 손실됨
- 코드 아키텍처가 점차 왜곡되고 스파게티화됨
- AI 모델을 교체하거나 세션이 끝나면 온보딩 비용이 초기화됨

REPL Works는 이 문제의 원인이 AI의 지능 부족이 아니라, "프로젝트 기억의 연속성 결여(Project Discontinuity)"에 있다고 진단합니다.

# Core Insight

Projects outlive humans, sessions, and models.
AI 모델은 발전하고 세션은 종료되지만, 프로젝트는 계속 살아남아야 합니다.
프로젝트 지식은 채팅 로그가 아니라 Git 표준 문서로 보존되어야 합니다.

# Solution

REPL Works는 프로젝트의 현재 상태와 규칙을 설명하는 6대 표준 마크다운 문서를 제공합니다.

1. IDEAS.md (아이디어 가설 검증)
2. PITCHING_SCRIPT.md (존재 이유 및 핵심 카피)
3. PRODUCT_SPEC.md (제품 요구사항 Single Source of Truth)
4. TECH_STACK.md (기술 구현 제약 및 컨벤션)
5. ARCHITECTURE.md (시스템 청사진 및 모듈 경계)
6. TASKS.md (현재 마일스톤 및 세부 작업 계획)

# Target Audience

- Solo Founders, Indie Hackers
- Small Technical Teams
- AI-Native Product Builders
```
