이 문서의 목적은 제품 요구사항이나 시스템 구조를 정의하는 것이 아니다.

어떤 기술과 구현 규칙을 사용할지 명확하게 정의하는 것이다.

---

# Purpose

다음 질문에 답한다.

```text
어떤 언어와 프레임워크를 사용하는가?

어떤 버전을 사용하는가?

파일은 어디에 위치하는가?

어떤 네이밍과 구현 규칙을 따라야 하는가?
```

---

TECH_STACK.md는 구현 기술과 규칙의 기준이다.

컴포넌트 간 관계와 데이터 흐름은 ARCHITECTURE.md에서 정의한다.

---

# Inputs

일반적으로 다음 정보를 기반으로 작성한다.

- PRODUCT_SPEC.md
- 프로젝트의 실행 환경
- 승인된 기술 제약
- 검증된 운영 요구사항

---

# Outputs

다음 내용을 정의한다.

- 언어와 프레임워크
- 라이브러리
- 버전
- 파일 배치 규칙
- 네이밍 규칙
- 구현 제약
- 테스트 도구

---

# Lifecycle

PRODUCT_SPEC.md 이후, ARCHITECTURE.md 이전에 작성한다.

---

기술 선택이나 구현 규칙이 변경될 경우 업데이트한다.

제품 기능이나 컴포넌트 관계를 변경하는 문서는 아니다.

---

# Relationship

```text
IDEAS.md
↓
PITCHING_SCRIPT.md
↓
PRODUCT_SPEC.md
↓
TECH_STACK.md
↓
ARCHITECTURE.md
↓
TASKS.md
```

---

PRODUCT_SPEC.md는 무엇을 만들지 정의한다.

TECH_STACK.md는 어떤 기술과 규칙을 사용할지 정의한다.

ARCHITECTURE.md는 시스템이 어떻게 구성되고 동작하는지 정의한다.

TASKS.md는 현재 무엇을 해야 하는지 정의한다.

# Key Principle

좋은 TECH_STACK.md는 제품 기능이나 시스템 구조를 설명하지 않는다.

좋은 TECH_STACK.md는 구현을 일관되게 만드는 명시적인 규칙을 제공한다.
