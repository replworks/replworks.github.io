## 1. 개요 및 왜 도구가 필요한가?

REPL Works의 도구(Tools)는 독립된 별개의 유틸리티가 아닙니다. **검증된 Workflow, Prompt, Document 표준을 더 적은 토큰과 더 명확한 실행 단위로 자동화하기 위해 존재**합니다.

## 2. 도구의 진화 과정 (Tool Evolution)

REPL Works 생태계에서 도구는 수동 프로세스에서 시작하여 충분히 반복 검증된 과업만 순차적으로 자동화 도구로 승격됩니다.

## 3. 공식 도구 모음 (Current Official Tools)

### 1. AI Issue Publisher (`ai-issue`)

생각과 아이디어를 Execution AI가 오버 스코프 없이 즉시 실행할 수 있는 GitHub Issue 포맷으로 변환하는 CLI 도구입니다.

<ValueFlow from="Raw Idea / Discussion" to="Actionable GitHub Issue" />

- **주요 기능**: 이슈 템플릿 자동화, 표준 수락 조건(Acceptance Criteria) 생성, AI 친화적 과업 정의
- [AI Issue Publisher 도구 상세보기](/tools/ai-issue)

---

### 2. REPL CLI (`repl-cli`)

로컬 프로젝트 실행 환경을 초기화하고, AI 에이전트의 실행 결과를 결정론적으로 관리·검증하는 CLI 도구입니다.

- **주요 기능**: 프로젝트 환경 초기화, 세션 실행 관리, AI 렌더링 결과 스키마 검증, 실행 상태 기록
- [REPL CLI 도구 상세보기](/tools/repl-cli)

---

## 4. 프레임워크 관계도 (Ecosystem Relationship)

도구는 REPL Works 프레임워크를 대체하는 것이 아니라, 프레임워크 준수를 더 빠르고 정확하게 도와주는 서포터입니다.

```text
좋은 도구는 새로운 프로세스를 발명하지 않습니다.
좋은 도구는 이미 검증된 프로세스를 더 적은 비용으로 자동화합니다.
```
