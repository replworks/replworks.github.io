## 🎯 프롬프트 목적

제품 명세를 실제로 구현하기 위해 필요한 언어, 프레임워크, 폴더 구조, 네이밍 규칙 및 명확한 구현 제약 조건을 정리합니다.

이 단계에서는 아직 전체 모듈 간 데이터 흐름을 설계하지 않습니다. **제품 요구사항을 만족하는 데 직접적으로 필요한 기술 명세와 가이드라인만 명확히 고정**하는 것이 목표입니다.

## 💡 사용 방법 & 대화 가이드

1. **사전 준비**: `PRODUCT_SPEC.md` 작성이 끝난 후, `ARCHITECTURE.md` 설계 전 단계에서 사용합니다.
2. **요구사항 기반 선택**: 불필요하거나 과도한 오버엔지니어링 기술 스택을 배제하고, `PRODUCT_SPEC.md` 근거가 있는 기술 스택만 선택하도록 유도합니다.

Do not describe user flows.

- Languages
- Frameworks
- Libraries
- Versions
- File Placement
- Naming Rules
- Implementation Constraints
- Testing Tools

If a decision cannot be justified by PRODUCT_SPEC.md, identify it as unresolved.

Prefer explicit constraints over general preferences.
