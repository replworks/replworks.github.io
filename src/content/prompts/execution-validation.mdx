## 🎯 프롬프트 목적

코드 생성을 시작하기 전에 작성된 주요 상위 문서(`PRODUCT_SPEC.md`, `TECH_STACK.md`, `ARCHITECTURE.md`, `TASKS.md`, `AGENTS.md`) 간의 충돌이나 누락 요소가 없는지 전체 종합 검증을 수행합니다.

이 단계는 새로운 기능을 제안하거나 추가하는 것이 아닙니다. **실제 코딩 작업에 착수했을 때 AI나 개발자가 막히는 지점(Blocker)이 없는지 선제적으로 점검하는 것**이 목적입니다.

---

## 📦 생성 산출물

```text
Validation Report
```

---

## 💡 사용 방법 & 대화 가이드

1. **사전 준비**: 상위 명세 문서 4종(`PRODUCT_SPEC.md`, `TECH_STACK.md`, `ARCHITECTURE.md`, `TASKS.md`) 작성이 모두 완료된 후 코드 작성 직전에 실행합니다.
2. **블로커 질문 도출**: AI는 모호함이나 문서 간 불일치가 있을 경우 차단성 질문 목록만 생성하며, 질문이 없다면 바로 신뢰도 높게 구현을 시작할 수 있음을 확증합니다.

---

## 🤖 AI 프롬프트 원문

아래 프롬프트를 복사하여 AI 대화창 첫 메시지로 전달해 보세요.

````text
Review the following documents together:

- AGENTS.md
- PRODUCT_SPEC.md
- TECH_STACK.md
- ARCHITECTURE.md
- TASKS.md

Assume you are responsible for implementing the entire product.

Assume no additional information will be provided.

Your goal is to determine whether implementation can begin with confidence.

Generate only questions.

Do not answer questions.

Do not suggest improvements.

Do not suggest new features.

Do not redesign the product.

Do not modify requirements.

Focus on identifying:

- missing requirements
- missing architectural responsibilities
- missing implementation constraints
- ambiguous behavior
- conflicting definitions
- undefined ownership
- undefined flows
- undefined inputs
- undefined outputs
- contradictions between documents

Treat the five documents as a single implementation contract.

A question is valid only if it blocks implementation certainty.

Ignore:

- personal preferences
- alternative technologies
- feature ideas
- product strategy

Output only a numbered list of questions.

If no blocking questions exist, output:

```text
Implementation can begin with high confidence.
```

Optimize for implementation certainty.
````
