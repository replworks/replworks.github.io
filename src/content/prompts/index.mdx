## 1. REPL Works 프롬프트의 역할

REPL Works는 일회성 프롬프트 작성에 의존하는 단순 프롬프트 모음집이 아닙니다.

- **문서(Document)**는 프로젝트의 영구적 기억(Project Memory)을 정의합니다.
- **프롬프트(Prompt)**는 그 프로젝트 기억을 일관되고 검증된 형태로 생성하고 활용하는 실행 도구입니다.

좋은 문서는 프로젝트의 구조와 맥락을 이해하게 만들고, **표준화된 프롬프트는 AI 에이전트로부터 매번 높은 품질의 일관된 결과를 도출**합니다.

## 2. REPL Works 표준 프롬프트 라이브러리 (Prompt Library)

REPL Works는 개발 파이프라인 단계에 맞춰 **총 9개의 표준 프롬프트**를 제공합니다.

### A. 기획 및 아이디어 정의 단계 (Planning Phase)

#### 1. Idea Refinement (아이디어 정제)

기획자와 Discussion AI가 대화하며 아이디어와 비즈니스 가설을 다듬고 정제합니다. 최종 확정 및 문서 작성은 기획자가 담당합니다.

- **생성 대상**: `IDEAS.md`
- [Idea Refinement 프롬프트 보기](/prompts/idea-refinement)

#### 2. Pitch Creation (피치 작성)

프로젝트의 목적과 차별성을 핵심 카피라인과 짧은 피치 스크립트로 압축 정리합니다.

- **생성 대상**: `PITCHING_SCRIPT.md`
- [Pitch Creation 프롬프트 보기](/prompts/pitch-creation)

---

### B. 제품 및 시스템 사양 정의 단계 (Specification Phase)

#### 3. Product Specification (제품 정의 명세)

제품의 도메인 비전, 타겟 유저, 정보 아키텍처 및 세부 기능 요구사항 규격을 구조화합니다.

- **생성 대상**: `PRODUCT_SPEC.md`
- [Product Specification 프롬프트 보기](/prompts/product-specification)

#### 4. Tech Stack (기술 사양 정의)

사용 기술, 언어 버전, 파일 배치 규칙, Naming Rule 등 구현 컨벤션을 정의합니다.

- **생성 대상**: `TECH_STACK.md`
- [Tech Stack 프롬프트 보기](/prompts/tech-stack)

#### 5. Architecture Design (아키텍처 설계)

시스템 컴포넌트 구조, 모듈 간 관계, 데이터 흐름 및 라우팅 설계를 정의합니다.

- **생성 대상**: `ARCHITECTURE.md`
- [Architecture Design 프롬프트 보기](/prompts/architecture-design)

#### 6. Task Generation (작업 계획 수립)

아키텍처와 제품 명세를 바탕으로, Execution AI가 1-Prompt = 1-Task로 즉시 수행 가능한 실행 마일스톤 목록을 생성합니다.

- **생성 대상**: `TASKS.md`
- [Task Generation 프롬프트 보기](/prompts/task-generation)

---

### C. 검증 및 리뷰 단계 (Review & Validation Phase)

#### 7. Execution Validation (구현 준비 상태 검증)

Execution AI가 임의 추측 없이 코드 구현을 시작할 수 있도록, 5대 상위 문서 간의 충돌이나 빠진 영역이 없는지 사전 검증합니다.

- **검증 대상**: `PRODUCT_SPEC.md`, `TECH_STACK.md`, `ARCHITECTURE.md`, `TASKS.md`, `AGENTS.md`
- [Execution Validation 프롬프트 보기](/prompts/execution-validation)

#### 8. Architecture Review (아키텍처 명세 검토)

작성된 `ARCHITECTURE.md`가 `PRODUCT_SPEC.md` 요구사항 및 `TECH_STACK.md` 구현 제약을 충족하는지 검토합니다.

- **검토 대상**: `PRODUCT_SPEC.md`, `TECH_STACK.md`, `ARCHITECTURE.md`
- [Architecture Review 프롬프트 보기](/prompts/architecture-review)

#### 9. Task Review (작업 계획 검토)

`TASKS.md`에 나열된 마일스톤이 제품 요구사항과 아키텍처 설계를 빠짐없이 반영하고 있는지 검토합니다.

- **검토 대상**: `PRODUCT_SPEC.md`, `TECH_STACK.md`, `ARCHITECTURE.md`, `TASKS.md`
- [Task Review 프롬프트 보기](/prompts/task-review)

## 4. 핵심 원칙 (Core Principles)

- **Reusable (재사용성)**: 개인 프롬프트가 아닌 프로젝트 팀 전체가 재사용 가능한 표준 자산입니다.
- **Versioned (버전 관리)**: 모든 프롬프트 개정 이력은 Git 커밋으로 관리됩니다.
- **Project-Proven (검증된 프롬프트)**: 실제 프로덕션 프로젝트를 완성해 보며 검증된 프롬프트만 공식 라이브러리에 등록합니다.
- **Continuously Improved (지속적 진화)**: 새로운 AI 모델의 특성과 개발 요구사항에 맞춰 프롬프트를 갱신합니다.
